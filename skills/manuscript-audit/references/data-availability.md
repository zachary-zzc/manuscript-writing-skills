# Data availability and reuse

Use when drafting or auditing a Data/Code Availability statement, planning data sharing, or checking data/code access in a submission package. A local wording edit checks only affected identifiers, access conditions and claims. A complete sharing plan or package audit covers the supporting data and code within its agreed scope; it does not make unrelated manuscript work a repository audit. Apply verified journal, funder and data-type requirements at the actual submission stage.

## Map supporting material to an access route

In the existing working record, map each relevant dataset or code release to the result or display it supports, its source and version, repository record or persistent identifier, access route, restrictions and citation. Distinguish generated raw data, processed data, figure source data, reused datasets and code when those objects exist. Do not force one DOI per file or invent identifiers for unfinished deposits.

Identify whether material is public, controlled-access, included in the paper or supplement, reused from a public source, restricted by a third party, or available through a justified request procedure. State the actual route and its conditions. A generic request-only sentence does not explain who can obtain which material or how; a legitimate restriction does not require the material to become public.

For datasets that support conclusions, retain the appropriate dataset citation and version as well as the availability statement. Prefer durable repository records or assigned identifiers to temporary sharing links. Check a mandated repository when one applies; do not replace a valid existing deposit merely to follow a preferred service.

## Verify access and reuse separately

For material in scope, verify that the identifier resolves to the intended record and version, and that its files and access conditions agree with the manuscript and supplement. Where permitted, test public or reviewer access without relying on the author's authenticated session. If that cannot be tested, record access as unverified; a landing page alone does not prove that the files are accessible. Do not expose private review links or credentials in public artifacts.

Inspect enough of the deposited files to support the claimed checks. Confirm that the README or data dictionary explains the relevant file contents, variables, units, missing-value codes, processing and versions. Keep raw and processed material distinguishable and map figure source data to the applicable panels or tables. For a multi-file archive, check that its manifest makes the contents identifiable; do not require a new manifest for a simple, already clear record.

Check whether the stated licence and reuse conditions match the repository record and known rights. Restricted or third-party material needs a clear permitted access or permission route. Missing rights information remains unresolved; do not apply an open licence, change restrictions, upload files or create a deposit as a side effect of manuscript work.

Report statement consistency, record resolution, file access and reuse documentation separately. A successful link check does not establish FAIR compliance or submission readiness. Escalate a gap according to its effect on verification and the applicable requirements, not a universal rule that every manuscript must use the same public-data package.

Adaptation provenance is recorded in [Nature integration](../../manuscript-workflow/references/nature-integration.md). These checks use existing evidence and access permissions and add no approval checkpoints or external runtime.
